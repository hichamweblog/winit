# Winit — مساحتك للإنجاز

تطبيق إنتاجية عربي، باتجاه RTL، يجمع المهام والمشاريع والعادات ومؤقت التركيز في مساحة شخصية هادئة. يستلهم سير العمل من أدوات مثل TickTick، مع تركيز خاص على أهدافك: البرمجة، الإنجليزية، العلوم الشرعية، العربية، الثقافة العامة، والقرآن والرياضة.

> **الحالة الحالية:** نسخة MVP قابلة للتشغيل محلياً. واجهة عربية متجاوبة، بيانات محلية دائمة، ومخطط بيانات يمهّد لتعدد مساحات العمل. لا توجد مصادقة متعددة المستخدمين أو نشر عام آمن بعد؛ لا تفتح نسخة MVP على الإنترنت قبل إضافة المصادقة والعزل والتحقق الأمني.
>
> **تنبيه خصوصية مهم:** جميع زوار النسخة التجريبية يتشاركون مساحة وبيانات ثابتة واحدة، وواجهات الكتابة غير محمية بتسجيل الدخول. تحفظ اليوميات كنص عادي في SQLite، بلا تشفير على مستوى التطبيق. استخدمها محلياً فقط ولا تدوّن كلمات مرور أو أسراراً أو معلومات شخصية حساسة.

## تشغيل التطبيق

يتطلب Node.js 20 أو أحدث.

```bash
npm install
npm run dev
```

يفتح التطبيق على `http://localhost:3000`. أمر `dev` يزامن مخطط SQLite، ويضيف بيانات البداية عند الحاجة، ثم يشغّل Next.js. بياناتك المحلية محفوظة في `data/winit.db` (مستثناة من Git).

### أوامر مفيدة

```bash
npm run typecheck  # فحص TypeScript
npm test           # اختبارات التواريخ والمؤقت والعادات والمهام والأولويات
npm run build      # بناء إنتاجي
npm run db:push    # مزامنة المخطط مع SQLite
npm run db:seed    # إضافة مساحة وبيانات البداية (آمن للتكرار)
npm run db:reset   # حذف قاعدة البيانات المحلية وإعادتها للحالة الابتدائية
```

يمكن تحديد موقع قاعدة البيانات بمتغير البيئة `DATABASE_URL`، مثلاً `file:./data/winit.db`.

## ما يعمل الآن

- لوحة **اليوم** مع عدد المهام، وقت التركيز، متابعة العادات، وإيقاع التركيز الأسبوعي.
- قوائم اليوم والقادم وصندوق الوارد وكل المهام، مع إنشاء المشاريع وتعديل اسمها ووصفها وهدف التركيز الأسبوعي ولونها وأيقونتها وحذفها. عند حذف مشروع تنتقل مهامه إلى صندوق الوارد بدلاً من ضياعها.
- إضافة المهام وتعديل المشروع والأولوية والموعد والملاحظات والوسوم وعدد جلسات التركيز والحالة، وإنجازها أو حذفها بعد تأكيد.
- مصفوفة أيزنهاور، وتقويم أسبوعي ببطاقات أيام قابلة للتمرير على الهاتف، وصفحة عادات مع تعديل الاسم والوصف والهدف والنوع والوحدة والتذكير واللون والأيقونة، أو حذف العادة وسجلّاتها. سلاسل العادات لا تحتسب اليوم إلا عند بلوغ الهدف، وتسمح بامتداد السلسلة إلى الأمس قبل انتهاء اليوم.
- **دفتر يوميات**: تدوينات مؤرخة مع عنوان اختياري ومزاج اختياري، بحث نصّي، صفحات للأقدم، وتعديل وحذف مع تأكيد. توجد نقطة دخول من لوحة اليوم، ومن تبويب الهاتف، ومن القائمة الجانبية. بيانات اليوميات تحفظ في SQLite.
- مؤقت بومودورو قابل للتخصيص (10–90 دقيقة) ومؤقت تصاعدي، مرتبطان اختيارياً بمهمة. مدة بومودورو تحفظ على الجهاز. حساب المؤقت مبني على الطوابع الزمنية، لا على عدد مرات `setInterval`، لذلك يبقى الوقت صحيحاً عند تبديل التبويب.
- شريط تنقل الهاتف قابل للتخصيص: اختر حتى أربعة أقسام؛ الاختيار يحفظ محلياً، وتبقى بقية الصفحات في قائمة «المزيد».
- واجهة عربية RTL مرنة، بوضع فاتح/داكن محفوظ يتبع تفضيل النظام عند أول زيارة؛ يحافظ الوضع الداكن المائل إلى الأزرق على الحدود والظلال وبطاقات Sticker نفسها المستخدمة في الوضع الفاتح.
- Tajawal للعناوين، Readex Pro للنصوص، وNoto Naskh Arabic للتفاصيل الصغيرة. استُخدم Readex Pro كأقرب خط متاح لاسم Reader Pro.
- بيانات بداية لمشاريع البرمجة والإنجليزية والعلوم الشرعية والعربية والثقافة العامة، وعادات القرآن والرياضة والإنجليزية.

## البنية التقنية

اختيرت بنية بسيطة وقابلة للتشغيل محلياً أولاً، بدلاً من اعتماد كل اقتراح تقني في المسودة:

- **Next.js 15 + React 19 + TypeScript** للواجهة وواجهات API.
- **SQLite + Drizzle ORM** لتسهيل البدء دون خادم قاعدة بيانات منفصل. يمكن لاحقاً الانتقال إلى PostgreSQL بإضافة مخطط/مهايئ مناسب دون تغيير نموذج المجال بالكامل.
- **Zod** للتحقق من مدخلات API، و **Lucide** للأيقونات.
- واجهات API داخل `src/app/api/[...path]/route.ts`، منطق تواريخ ومؤقت نقي في `src/lib/core.ts`، ومخطط المجال في `src/db/schema.ts`.

### قابلية التوسع إلى SaaS

المخطط يتضمن المستخدمين ومساحات العمل والعضويات والأدوار، وكل سجل إنتاجية مرتبط بـ `workspaceId`، مع فهارس للقراءة اليومية. هذه نقطة بداية مناسبة لعزل المستأجرين، وليست بديلاً عن تنفيذ العزل الأمني. حالياً تستخدم نسخة MVP مساحة تجريبية ثابتة (`DEMO_WORKSPACE_ID`) بلا تسجيل دخول. قبل الإطلاق العام ينبغي:

1. إضافة مصادقة موثوقة، جلسات آمنة، واستعادة الحساب.
2. اشتقاق المستخدم ومساحة العمل من الجلسة الموثّقة، لا من ثوابت أو مدخلات العميل.
3. التحقق من صلاحيات العضوية على كل عملية وفرض العزل على مستوى قاعدة البيانات/الاستعلامات.
4. إضافة اختبارات API وتكامل، تحديد المعدل، سجل تدقيق، نسخ احتياطي، ومراقبة.
5. ترحيل SQLite إلى PostgreSQL عند الحاجة لتشغيل متعدد النسخ أو أحمال SaaS.

## هيكل المشروع

```text
src/
├── app/
│   ├── api/[...path]/route.ts  # API للمهام، المشاريع، العادات، التركيز، واليوميات
│   ├── globals.css             # التصميم المتجاوب
│   ├── layout.tsx              # العربية وRTL وبيانات الصفحة
│   └── page.tsx                # مساحة العمل التفاعلية
├── db/
│   ├── index.ts                # SQLite + Drizzle
│   ├── schema.ts               # الجداول والعلاقات متعددة المساحات
│   └── seed.ts                 # بيانات بداية قابلة لإعادة التشغيل
└── lib/
    ├── core.ts                 # تواريخ، مؤقت، وفرز الأولويات (دوال نقية)
    └── core.test.ts            # اختبارات المنطق الأساسي
```

## الخطوات التالية المقترحة

1. تسجيل الدخول وإدارة الحساب والمساحات، ثم استبدال مساحة العرض التجريبية بسياق مستخدم موثق. هذا مطلوب قبل النشر العام.
2. تحسين تسجيل العادات الكمية/المدة على لوحة اليوم، وإضافة التذكيرات.
3. مهام متكررة ومهام فرعية وقوائم ذكية قابلة للتخصيص.
4. سحب وإفلات Time-blocking وتقارير وقت بحسب المشروع.
5. اختبارات واجهة E2E، ثم نشر تدريجي مع قاعدة PostgreSQL ونسخ احتياطي.

للاطلاع على المراجعة التفصيلية للواجهة وتجربة المستخدم والمنطق والرحلات والاستخدام على الهاتف، راجع [`docs/product-review.md`](docs/product-review.md).
