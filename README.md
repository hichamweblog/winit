# Winit — مساحتك للإنجاز

تطبيق إنتاجية عربي، باتجاه RTL، يجمع المهام والمشاريع والعادات ومؤقت التركيز في مساحة شخصية هادئة. يستلهم سير العمل من أدوات مثل TickTick، مع تركيز خاص على أهدافك: البرمجة، الإنجليزية، العلوم الشرعية، العربية، الثقافة العامة، والقرآن والرياضة.

> **الحالة الحالية:** مصادقة حقيقية بالجلسات، وعزل كامل للبيانات لكل حساب، وترويسات أمنية، وترحيلات مُودَعة في المستودع. كل واجهة API تشتق المستخدم ومساحة العمل من الجلسة الموثّقة، ولا تقبل بيانات حساب آخر. مناسب للنشر على نسخة واحدة خلف HTTPS.
>
> **ما ينقص قبل الإطلاق العام:** استعادة كلمة المرور والتحقق من البريد، حذف الحساب وتصدير البيانات، سياسة CSP بلا `unsafe-inline`، وتحديد معدل يعمل عبر عدة نسخ (الحالي في ذاكرة العملية). القائمة الكاملة والصريحة في [`docs/production-readiness-implementation.md`](docs/production-readiness-implementation.md).
>
> **تنبيه خصوصية:** اليوميات تحفظ كنص عادي في SQLite بلا تشفير على مستوى التطبيق؛ اعتمد على تشفير القرص. لا تدوّن كلمات مرور أو أسراراً.
>
> **وضع التجربة (`WINIT_DEMO_MODE=1`):** مساحة واحدة مشتركة ومفتوحة للجميع بلا تسجيل دخول، للعرض فقط. معطّل افتراضياً، وتظهر حالته في `/api/health` وكشريط تحذير في الواجهة. **لا تفعّله أبداً على نشر يحتوي بيانات حقيقية.**

## تشغيل التطبيق

يتطلب **Node.js 22** أو أحدث (مثبّت في `.nvmrc` و`engines`).

```bash
npm ci
npm run dev:setup   # ترحيلات + بيانات بداية (مرة واحدة)
npm run dev
```

يفتح التطبيق على `http://localhost:3000`. أمر `dev` يشغّل Next.js فقط: لا يزامن المخطط ولا يضيف بيانات ضمنية، حتى لا يمسّ تشغيل التطوير بياناتك. بياناتك المحلية في `data/winit.db` (مستثناة من Git).

أنشئ حساباً من شاشة الدخول لتحصل على مساحة خاصة بك. لعرض التطبيق بلا حساب، شغّله بـ `WINIT_DEMO_MODE=1`.

### النشر

```bash
npm ci
npm run bootstrap   # فحص Node + ترحيلات، بلا أي بيانات بداية
npm run build
npm start
```

اضبط `DATABASE_URL` على قرص دائم، و`WINIT_PUBLIC_ORIGIN` على نطاقك العام. كل المتغيرات موثّقة في [`.env.example`](.env.example). يوجد `Dockerfile` متعدد المراحل يعمل بمستخدم غير root مع فحص صحة.

### أوامر مفيدة

```bash
npm run check         # typecheck + اختبارات الوحدة + بوابة نظام التصميم
npm run test:api      # 99 فحصاً أمنياً ضد خادم عامل (يتطلب وضع تجربة معطّلاً)
npm run build         # بناء إنتاجي

npm run db:generate   # توليد ترحيل بعد تغيير المخطط (يُودَع في Git)
npm run db:migrate    # تطبيق الترحيلات المُودَعة
npm run db:seed       # بيانات بداية — يرفض العمل في الإنتاج
npm run db:backup     # نسخة احتياطية متسقة عبر SQLite backup API + فحص سلامة
npm run db:reset -- --yes  # للتطوير فقط: نسخة احتياطية أولاً، ثم إعادة بناء
npm run db:clean-demo -- --yes  # حذف بقايا الاختبارات من مساحة العرض (نسخة احتياطية أولاً)
npm run sessions:purge     # حذف الجلسات المنتهية (شغّله يومياً)
```

يمكن تحديد موقع قاعدة البيانات بمتغير البيئة `DATABASE_URL`، مثلاً `file:./data/winit.db`.

## ما يعمل الآن

- لوحة **اليوم** مع عدد المهام، وقت التركيز، متابعة العادات، وإيقاع التركيز الأسبوعي.
- قوائم اليوم والقادم وصندوق الوارد وكل المهام، مع إنشاء المشاريع وتعديل اسمها ووصفها وهدف التركيز الأسبوعي ولونها وأيقونتها وحذفها. عند حذف مشروع تنتقل مهامه إلى صندوق الوارد بدلاً من ضياعها.
- إضافة المهام وتعديل المشروع والأولوية والموعد والملاحظات والوسوم وعدد جلسات التركيز والحالة، وإنجازها أو حذفها بعد تأكيد.
- **تقويم شهري** مبني على `react-day-picker`: شبكة شهر واحد تبدأ بالسبت، نقاط كثافة بدل النص داخل الخلايا، وقائمة مهام اليوم المحدد بجانبها. شبكة ARIA مع تنقّل كامل بلوحة المفاتيح، ولا تداخل عند أي عرض.
- **الإعدادات**: قسم واحد يجمع المظهر ومدة التركيز وتخصيص شريط الهاتف والحساب، وكل تغيير يُحفظ فوراً.
- **الإحصائيات**: وقت التركيز والمهام المنجزة وثبات العادات وأطول سلسلة أيام، على نطاقات 7/30/90 يوماً، مع رسم يومي وآخر 8 أسابيع وتوزيع حسب الأولوية. لكل رسم بديل نصّي يقرؤه قارئ الشاشة.
- **سجل العادات** يعرض نطاقات **شهر**/3 أشهر/6 أشهر/سنة. في وضع الشهر تكبر الخلايا ويظهر رقم كل يوم وتسميات الأيام السبعة. التلميح مختصر (`6 نوفمبر · 5/5`) ومثبّت داخل حدود الشاشة فلا يتقطّع على الهاتف، بينما يحتفظ `aria-label` بالتاريخ الكامل والوحدة لقارئ الشاشة.
- **مخطط المساهمات بأسلوب GitHub:** شبكة 7 أيام × أسابيع، خمسة مستويات شدة حسب نسبة الهدف المحقّق، تسميات أشهر وأيام، مفتاح «أقل/أكثر»، تلميح عند التأشير أو التركيز، ونطاقات 3 أشهر/6 أشهر/سنة. المحور الزمني يتدفق من اليمين إلى اليسار، ويفتح على أحدث الأسابيع. تنقّل كامل بالأسهم مع تسمية نصّية دقيقة لكل يوم، وملخّص لأيام الإنجاز والنسبة والسلسلة الحالية وأطول سلسلة.
- **دفتر يوميات**: تدوينات مؤرخة مع عنوان اختياري ومزاج اختياري، بحث نصّي، صفحات للأقدم، وتعديل وحذف مع تأكيد. توجد نقطة دخول من لوحة اليوم، ومن تبويب الهاتف، ومن القائمة الجانبية. بيانات اليوميات تحفظ في SQLite.
- مؤقت بومودورو قابل للتخصيص (10–90 دقيقة) ومؤقت تصاعدي، مرتبطان اختيارياً بمهمة. مدة بومودورو تحفظ على الجهاز. حساب المؤقت مبني على الطوابع الزمنية، لا على عدد مرات `setInterval`، لذلك يبقى الوقت صحيحاً عند تبديل التبويب.
- شريط تنقل الهاتف قابل للتخصيص من الإعدادات: حتى أربعة أقسام، والبقية في «المزيد». زر إضافة عائم يراعي حواف الشاشة الآمنة، وأهداف لمس 44px كحدّ أدنى.
- **كل التأكيدات مودالات داخل التطبيق** — لا `alert` ولا `confirm` ولا `prompt`. حذف مهمة أو مشروع أو عادة أو تدوينة، وإغلاق محرّر فيه تغييرات، كلها مودال `alertdialog` بتركيز أول على «إلغاء»، وEscape أو الخلفية للإلغاء.
- **الأولوية علم ملوّن بلا كلمات**، وعدد الجلسات رقم وأيقونة فقط. المعنى الذي كان في النص صار اسماً مقروءاً بـ ARIA. أزرار التعديل والحذف تظهر عند المرور أو التركيز، ودائماً على اللمس، في المهام واليوميات والعادات والمشاريع.
- واجهة عربية RTL مرنة، بوضع فاتح/داكن محفوظ يتبع تفضيل النظام عند أول زيارة؛ يحافظ الوضع الداكن المائل إلى الأزرق على الحدود والظلال وبطاقات Sticker نفسها المستخدمة في الوضع الفاتح.
- El Messiri للعناوين، Readex Pro للواجهة، وNoto Naskh Arabic لقراءة اليوميات، حسب نظام تصميم Calm Sea. الأرقام لاتينية دائماً (`ar-u-nu-latn`).
- **منتقي أوسع للمشاريع:** 24 أيقونة موزّعة على خمس مجموعات (الأساسية، العمل والدراسة، العبادة والصحة، الإبداع، الحياة) و19 لوناً ثابتاً، لكل منها اسم عربي. الألوان الجديدة مشتقة ومُبرهنة التباين آلياً، وتعمل في الوضعين الفاتح والداكن. منتقي ألوان العادات يستخدم اللوحة نفسها.
- **34 أيقونة للعادات** في ست مجموعات (الأساسية، العبادة، الحركة، الصحة والراحة، العقل والتعلم، الحياة) مع 19 لوناً، وتحقّق الخادم مشتقّ من الكتالوج نفسه.
- بيانات بداية لمشاريع البرمجة والإنجليزية والعلوم الشرعية والعربية والثقافة العامة، وعادات القرآن والرياضة والإنجليزية.

## البنية التقنية

اختيرت بنية بسيطة وقابلة للتشغيل محلياً أولاً، بدلاً من اعتماد كل اقتراح تقني في المسودة:

- **Next.js 15 + React 19 + TypeScript** للواجهة وواجهات API.
- **SQLite + Drizzle ORM** لتسهيل البدء دون خادم قاعدة بيانات منفصل. يمكن لاحقاً الانتقال إلى PostgreSQL بإضافة مخطط/مهايئ مناسب دون تغيير نموذج المجال بالكامل.
- **Zod** للتحقق الصارم من مدخلات API (كائنات `.strict()` ترفض أي حقل مجهول)، و**Tabler Icons** للأيقونات عبر طبقة دلالية واحدة في `src/app/icons.tsx`.
- **المصادقة:** scrypt من `node:crypto` لكلمات المرور، وجلسات تُخزَّن كبصمة SHA-256، وكوكيز `HttpOnly` + `SameSite=Lax` + `Secure`، مع رمز CSRF مزدوج الإرسال.
- واجهات API داخل `src/app/api/[...path]/route.ts`، منطق تواريخ ومؤقت نقي في `src/lib/core.ts`، ومخطط المجال في `src/db/schema.ts`.

### قابلية التوسع إلى SaaS

كل سجل إنتاجية مرتبط بـ `workspaceId`، وكل واجهة API تشتق المستخدم ومساحة العمل من الجلسة الموثّقة. العزل مُختبَر فعلياً بحسابين: القراءة والتعديل والحذف والمراجع الخارجية عبر الحسابات ترجع 404 في الاتجاهين.

**ما نُفّذ:** مصادقة وجلسات آمنة، عزل المستأجرين، تحقق صارم، حماية CSRF ومصدر الطلب، تحديد معدل، ترويسات أمنية وCSP، نقطة صحة، سجلّات بمعرّف طلب، ترحيلات مُودَعة، نسخ احتياطي، وحدود أخطاء.

**ما بقي قبل SaaS فعلي:**

1. استعادة كلمة المرور، التحقق من البريد، حذف الحساب وتصدير بياناته.
2. تحديد معدل موزّع (Redis) — الحالي في ذاكرة العملية ولا يعمل عبر عدة نسخ.
3. CSP بلا `unsafe-inline` عبر nonce من middleware.
4. سجل تدقيق ومراقبة وتنبيهات.
5. ترحيل SQLite إلى PostgreSQL، وترقيم صفحات اليوميات بالمؤشر بدل الإزاحة.

## هيكل المشروع

```text
src/
├── app/
│   ├── api/[...path]/route.ts  # API البيانات، معزول بالجلسة
│   ├── api/auth/               # تسجيل، دخول، خروج، جلسة
│   ├── api/health/             # فحص الحياة والجاهزية
│   ├── components/             # HabitHistory، AuthGate، CalendarView، StatsView، SettingsView،
│   │                           # ConfirmDialog، useDialogFocus، atoms
│   ├── icons.tsx               # طبقة الأيقونات الدلالية (Tabler)
│   ├── habit-icons.tsx         # خريطة أيقونات العادات
│   ├── project-icons.tsx       # خريطة أيقونات المشاريع
│   ├── globals.css             # التصميم المتجاوب
│   ├── layout.tsx              # العربية وRTL وبيانات الصفحة
│   └── page.tsx                # مساحة العمل التفاعلية
├── db/
│   ├── index.ts                # SQLite + Drizzle
│   ├── schema.ts               # الجداول والعلاقات متعددة المساحات
│   └── seed.ts                 # بيانات بداية قابلة لإعادة التشغيل
└── lib/
    ├── core.ts                 # تواريخ، مؤقت، وفرز الأولويات (دوال نقية)
    ├── habit-history.ts        # حساب شبكة المساهمات والسلاسل (نقي، مُختبَر)
    ├── stats.ts                # حساب الإحصائيات (نقي، مُختبَر)
    ├── semantics.ts            # الأولوية والأسماء المقروءة (نقي، مُختبَر)
    ├── types.ts                # أشكال بيانات مساحة العمل
    ├── habit-icons.ts          # كتالوج أيقونات العادات (بلا React)
    ├── project-icons.ts        # كتالوج أيقونات المشاريع (بلا React)
    ├── goals.ts                # لوحة ألوان الأهداف
    ├── client-api.ts           # عميل المتصفح مع رمز CSRF
    └── server/                 # password، auth، http، dto (خادم فقط)
```

## الخطوات التالية المقترحة

1. استعادة الحساب والتحقق من البريد وحذف الحساب وتصدير البيانات — أهم ما ينقص قبل النشر العام.
2. تحسين تسجيل العادات الكمية/المدة على لوحة اليوم، وإضافة التذكيرات.
3. مهام متكررة ومهام فرعية وقوائم ذكية قابلة للتخصيص.
4. سحب وإفلات Time-blocking وتقارير وقت بحسب المشروع.
5. اختبارات واجهة E2E، ثم نشر تدريجي مع قاعدة PostgreSQL ونسخ احتياطي.

للاطلاع على المراجعة التفصيلية للواجهة وتجربة المستخدم والمنطق والرحلات والاستخدام على الهاتف، راجع [`docs/product-review.md`](docs/product-review.md).
